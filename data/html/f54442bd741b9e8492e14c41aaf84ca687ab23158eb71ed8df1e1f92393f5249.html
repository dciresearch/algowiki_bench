Общее описание алгоритма

Задача декомпозиции графа

Метод рекурсивной координатной бисекции является одним из методов, применяемых для декомпозиции графов [1]. В прикладных задачах, как правило, граф представляет собой сетку в пространстве некоторой размерности. При численном решении задач механики сплошной среды с помощью методов конечных разностей или конечных элементов широко используется геометрический параллелизм, при котором сетка, покрывающая расчётную область, разбивается на множество доменов, каждый из которых обрабатывается отдельным процессором. Основная проблема связана с необходимостью решения задачи статистической балансировки загрузки, то есть равномерного распределения вычислительной нагрузки между процессорами за счёт выбора оптимальной декомпозиции сетки.

Критерии декомпозиции

В зависимости от специфики решаемой задачи, к виду декомпозиции графов могут быть предъявлены разные требования. Существует много критериев декомпозиции, однако наиболее классическим из них считается минимизация максимального веса исходящих из домена ребёр (в простейшем случае - минимизация числа разрезанных ребер). Среди других критериев можно выделить следующие:

  • выделение обособленных доменов;
  • минимизация максимальной степени доменов;
  • обеспечение связности доменов;
  • обеспечение связности множества внутренних узлов доменов.

Метод рекурсивной бисекции

Метод рекурсивной координатной бисекции является частным случаем более общего метода рекурсивной бисекции. В этом методе сетка последовательно за [math]\displaystyle{ k-1 }[/math] шаг делится на [math]\displaystyle{ k }[/math] частей. На первом шаге сетка делится на две части, далее каждая из полученных ранее частей также делится на две части и т.п. Конкретные алгоритмы деления сетки на две части (бисекции) и определяют метод рекурсивной бисекции. Соотношение размеров частей зависит количества доменов и процедуры вычисления желаемого числа вершин в каждой из формируемых частей графа.

Метод рекурсивной координатной бисекции

Для декомпозиции больших сеток применяют параллельные алгоритмы, предполагающие, что сетка уже распределена по процессорным узлам. Они эффективны, только если вершины распределены по процессорам компактными группами, а не произвольно. Однако к моменту начала работы алгоритмов декомпозиции, никакая декомпозиция сетки еще не найдена, поэтому требуется некоторый простой способ предварительного распределения графа по выполняющим декомпозицию процессорам. Для решения этой задачи и используется метод рекурсивной покоординатной бисекции. Несмотря на то, что он уступает по качеству формируемой декомпозиции некоторым другим методам, его целесообразно использовать на предварительном этапе, благодаря скорости работы, ориентированности на распределенную обработку и простоте.

Метод рекурсивной координатной бисекции основан на методе рекурсивной бисекции. Для разбиения сетки на две части используется следующая процедура:

  • выбирается одна из координатных осей;
  • множество вершин сортируется по этой координате;
  • отсортированное множество разбивается на две части, то есть указывается индекс [math]\displaystyle{ i }[/math] такой, что в первую часть попадают вершины с номерами меньшими либо равными [math]\displaystyle{ i }[/math], а во вторую - оставшиеся вершины; геометрически это соответствует гиперплоскости, перпендикулярной выбранной оси, которая разбивает множество вершин сетки на две части, соотношение размеров которых зависит

Выбор координатной оси

В зависимости от критериев декомпозиции и других особенностей задачи могут быть использованы различные критерии выбора координатной оси вдоль, которой будет производится разбиение сетки на две части. Наиболее используемыми являются следующие:

  • Протяжённость области вдоль данной оси: для каждой оси вычисляется разность между максимумом и минимумом координат вершин сетки по данной оси, и выбирается ось с наибольшим значением этой величины;
  • Число разрезанных ребер при разбиении сетки вдоль данной оси: вершины упорядочиваются вдоль каждой из осей, и выбирается тот вариант, который приводит к наименьшему числу разрезанных ребер;

Математическое описание алгоритма

Исходные данные: граф [math]\displaystyle{ G = (V, E) }[/math], вложенный в [math]\displaystyle{ \mathbb{R}^N }[/math] (то есть каждая вершина этого графа - это точка в [math]\displaystyle{ N }[/math] мерном пространстве), и число [math]\displaystyle{ k }[/math] доменов, на которое нужно разбить граф. Под декомпозицией графа на [math]\displaystyle{ k }[/math] доменов понимается разбиение множества вершин [math]\displaystyle{ V }[/math] на [math]\displaystyle{ k }[/math] подмножеств [math]\displaystyle{ V_1, \dots, V_k }[/math] таких, что

[math]\displaystyle{ V = \bigcup_{i = 1}^k V_i }[/math] и [math]\displaystyle{ V_i \cap V_j = \varnothing }[/math] при [math]\displaystyle{ i \neq j }[/math].

С каждым доменом можно связать порождённый им подграф [math]\displaystyle{ G(V_i) = (V_i, E_i) }[/math], где [math]\displaystyle{ E_i \subseteq E }[/math] - множество рёбер, оба конца которых принадлежат домену.

Задача заключается в нахождении декомпозиции [math]\displaystyle{ V_1, \dots, V_k }[/math], доставляющей минимум некоторого функционала (см. соответствующий пункт), например, числа разрезанных рёбер [math]\displaystyle{ E_{\mbox{cut}} = |\{(u, v) \in E \mid u \in V_i, v \in V_j, i \neq j\}| = |E| - \sum_{i = 1}^k |E_i| }[/math].

Дадим формальное описание алгоритма. Как уже упоминалось, метод основан на алгоритме рекурсивной бисекции, поэтому представляет собой рекурсивную процедуру, на вход которой поступает граф [math]\displaystyle{ G = (V, E) }[/math] и число доменов [math]\displaystyle{ k }[/math], на которое нужно разбить множество вершин данного графа. Внутри этой процедуры выполняется следующая последовательность действий:

  • в зависимости от числа доменов вычисляется "желаемое" число доменов и вершин в каждой из частей разбиения;
  • вызывается процедура координатной бисекции для получения разбиения графа на две части;
  • для каждой из двух полученных частей рекурсивно вызывается описываемая процедура (если число доменов для этой части больше единицы).

Процедура координатной бисекции устроена следующим образом:

  • выбирается координатная ось [math]\displaystyle{ m^* \in \{1, \dots, N\} }[/math];
    • в случае максимизации протяженности: для каждой оси [math]\displaystyle{ m }[/math] вычисляется величина [math]\displaystyle{ l_m = \max_{v \in V} v_m - \min_{v \in V} v_m }[/math], и выбирается ось [math]\displaystyle{ m^* = \arg\max_{m \in \{1, \dots, N\}} l_m }[/math];
    • в случае минимизации числа разрезанных ребер: вершины упорядочиваются вдоль каждой из осей, для каждой оси вычисляется величина [math]\displaystyle{ E^m_{\mbox{cut}} }[/math], равная числу разрезанных ребер при разбиении вдоль данной оси, и выбирается ось [math]\displaystyle{ m^* = \arg\max_{m \in \{1, \dots, N\}} E^m_{\mbox{cut}} }[/math];
  • множество вершин сортируется по возрастанию координаты с номером [math]\displaystyle{ m^* }[/math];
  • отсортированный массив вершин делится на две (непрерывные) части в соответствии с желаемым числом вершин в каждой из частей;
    • как правило, выбирается индекс [math]\displaystyle{ i = \lfloor\frac{k+1}{2k}\rfloor \cdot |V| }[/math], соответствующий примерно равному разделению текущего графа на части;
  • первая часть состоит из вершин [math]\displaystyle{ v \in V }[/math] с индексами [math]\displaystyle{ j \leqslant i }[/math], вторая - с индексами [math]\displaystyle{ j \gt i }[/math].

Вычислительное ядро алгоритма

Вычислительное ядро алгоритма составляют сортировки массива вершин сетки по выбранной координате при каждом из [math]\displaystyle{ k - 1 }[/math] вызовов процедуры бисекции.

Также, в зависимости от критерия выбора координатной оси, требуются дополнительные вычисления:

  • В случае максимизации протяженности при каждом вызове требуется вычисление величины [math]\displaystyle{ l_m }[/math].
  • В случае минимизации числа разрезанных ребер при каждом вызове требуется сортировка по каждой из координат (таким образом, при каждом разбиении осуществляется [math]\displaystyle{ N }[/math] сортировок).

Макроструктура алгоритма

Как записано в описании ядра алгоритма, основную часть метода составляют множественные (всего [math]\displaystyle{ k-1 }[/math]) сортировки (функция argsort в коде в следующем разделе).

Схема реализации последовательного алгоритма

Опишем последовательную реализацию метода рекурсивной координатной бисекции, где выбор оси производится исходя из условия максимизации протяженности вдоль этой оси. Ниже представлен код данного алгоритма на языке Python 3. 

# Переменная для хранения результата работы алгоритма
partition = []

# V - numpy.ndarray размера |V| x N, k - число доменов
def recursive_bisection(V, k):

    global partition

    # Если текущая часть графа есть домен, добавляем ее к результату разбиения
    if (k <= 1):
        partition.append(V)
        return 

    # Вычисляем количество доменов в каждой из частей
    k1 = (k + 1) / 2
    k2 = k - k1
    
    # Производим разбиение  
    V1, V2 = bisect(V, k)

    # Рекурсивно разбиваем каждую из частей
    recursive_bisect(V1, k1) 
    recursive_bisect(V2, k2)
    
def bisect(V, k):
    # Вычисляем координату с наибольшей протяженностью
    t = V.max(axis=0) - V.min(axis=0)
    m = t.argmax()
    
    # Сортируем вершины по координате с номером m
    V_sorted = V[V[:, m].argsort()]

    # Вычисляем индекс для разбиения в соответствии с числом доменов
    ind = (k + 1) * V.shape[0] // (2 * k)

    return V_sorted[:ind, :], V_sorted[ind:, :]

Приведённый код предназначен для более подробного описания основных шагов в алгоритме, представляет собой лишь схему и не является максимально эффективным. Это сделано для того, чтобы код был более наглядным. В более эффективной реализации, например, вместо создания массивов в процедуре bisect можно везде оперировать только индексами.

Последовательная сложность алгоритма

Обозначим через [math]\displaystyle{ D_k(n) }[/math] сложность алгоритма рекурсивной координатной бисекции для декомпозиции графа с [math]\displaystyle{ n }[/math] вершинами на [math]\displaystyle{ k }[/math] доменов.

Определим величину [math]\displaystyle{ D(n) = D_n(n) }[/math]. Для [math]\displaystyle{ D(n) }[/math] имеет место следующее рекуррентное равенство:

[math]\displaystyle{ \begin{array}{l} D(n) = S(n) + 2D(\frac{n}{2}) \\ D(1) = S(1) = 0. \\ \end{array} }[/math], где [math]\displaystyle{ S(n) }[/math] - это сложность алгоритма сортировки массива из [math]\displaystyle{ n }[/math] элементов.

Пусть [math]\displaystyle{ S(n) = O(n\log_2{n}) }[/math] (например, для сортировки слиянием), тогда по теореме о рекуррентных соотношениях [2] для произвольного положительного [math]\displaystyle{ \varepsilon }[/math] имеет место оценка [math]\displaystyle{ D(n) \lesssim n^{1+\varepsilon} }[/math].

Величину [math]\displaystyle{ D_k(n) }[/math] можно явно посчитать по формуле [math]\displaystyle{ \sum\limits_{i=0}^{\lceil\log_2{k}\rceil}2^i S(\frac{n}{2^i}) }[/math]. Если использовать сортировку со сложностью [math]\displaystyle{ S(n) = O(n\log_2{n}) }[/math], то

[math]\displaystyle{ D_k(n) = }[/math] [math]\displaystyle{ O(\sum\limits_{i=0}^{\lceil\log_2{k}\rceil}2^i \frac{n}{2^i} \log_2{\frac{n}{2^i}}) = }[/math] [math]\displaystyle{ O(n\log_2(\prod\limits_{i=0}^{\lceil\log_2{k}\rceil}\frac{n}{2^i})) = }[/math] [math]\displaystyle{ O(n\log_2{\frac{n^{\log_2{k}}}{2^\frac{\log_2{k}(\log_2{k}+1))}{2}}}) = }[/math] [math]\displaystyle{ O(n(\log_2{n}\log_2{k} - \frac{\log^2_2{k}}{2})) = }[/math] [math]\displaystyle{ O(n\log_2{n}\log_2{k}) }[/math].

Таким образом, информационный граф представляет из себя бинарное дерево с [math]\displaystyle{ k }[/math] листьями. Ресурс параллелизма алгоритма

Данный алгоритм обладает координатным параллелизмом. Для декомпозиции графа с [math]\displaystyle{ n }[/math] вершинами на [math]\displaystyle{ k }[/math] доменов методом рекурсивной координатной бисекции в параллельном варианте требуется последовательно выполнить [math]\displaystyle{ \lceil\log_2{k}\rceil }[/math] ярусов. На [math]\displaystyle{ i }[/math]-ом ярусе будет выполнятся [math]\displaystyle{ 2^i }[/math] операций сортировки. Рассмотрим два случая распараллеливания нашего алгоритма:

  • Параллельное выполнение операций на каждом ярусе с использованием последовательного алгоритма сортировки со сложностью [math]\displaystyle{ O(n\log_2{n}) }[/math].
  1. На первом шаге один процессор производит сортировку всех вершин, разделяет граф на два подграфа и передает однин из подрафов новому процессору.
  2. На [math]\displaystyle{ i }[/math]-ом шаге каждый из уже получивший свой граф процессор производит сортировку всех вершин, разделяет граф на два подграфа и передает однин из подрафов новому процессору.

Тогда сложность нашего алгоритма равна:

[math]\displaystyle{ D_k(n) = O(\sum\limits_{i=0}^{\lceil\log_2{k}\rceil}\frac{n}{2^i} \log_2{\frac{n}{2^i}}) = }[/math] [math]\displaystyle{ n\sum\limits_{i=0}^{\lceil\log_2{k}\rceil}(\frac{\log_2{n}}{2^i} - \frac{i}{2^i}) = }[/math] [math]\displaystyle{ O(n\log_2{n}) - O(n) = O(n\log_2{n}) }[/math].

  • Параллельное выполнение операций на каждом ярусе с использованием параллельного алгоритма сортировки со сложностью [math]\displaystyle{ O(\log_2^2{n}) }[/math][3].

На каждом шаге производится параллельная сортировка вершин и разбиение графа на два подграфа. В этом случае

[math]\displaystyle{ D_k(n) = \sum\limits_{i=0}^{\lceil\log_2{k}\rceil}\log^2_2\frac{n}{2^i} = O(\log^2_2{n}\log_2{k}) = O(\log^3_2{n}) }[/math].

Известно [4], что оптимальная параллельная сортировка имеет сложность [math]\displaystyle{ O(\log_2{n}) }[/math]. В этом случае

[math]\displaystyle{ D_k(n) = \sum\limits_{i=0}^{\lceil\log_2{k}\rceil}\log_2\frac{n}{2^i} = O(\log_2{n}\log_2{k}) }[/math].

Входные и выходные данные алгоритма

Входные данные: граф [math]\displaystyle{ G = (V, E) }[/math], вложенный в [math]\displaystyle{ \mathbb{R}^N }[/math], и число [math]\displaystyle{ k }[/math] частей (доменов), на которое нужно разбить граф. Таким образом, помимо матрицы смежности (или любого другого представления графа) для каждой вершины [math]\displaystyle{ v \in V }[/math] задан набор её координат [math]\displaystyle{ v = (v_1, \dots, v_N) \in \mathbb{R}^N }[/math], поэтому [math]\displaystyle{ V }[/math] задаётся массивом [math]\displaystyle{ N }[/math]-мерных векторов или матрицей размера [math]\displaystyle{ |V| \times N }[/math].

Объём входных данных: [math]\displaystyle{ N|V| + |G| }[/math], где [math]\displaystyle{ |G| }[/math] - объём данных, представляющих граф [math]\displaystyle{ G }[/math], который в общем случае зависит от выбранного представления.

Выходные данные: [math]\displaystyle{ k }[/math] доменов графа [math]\displaystyle{ G }[/math], задающих его декомпозицию.

Объём выходных данных: [math]\displaystyle{ |V| }[/math] - для каждого домена достаточно хранить соответствующие вершинам из этого домена индексы строк в матрице, представляющей множество вершин.

Свойства алгоритма

Соотношение последовательной и параллельной сложности в случае неограниченных ресурсов является линейным (отношение [math]\displaystyle{ O(n\log{n}) }[/math] к [math]\displaystyle{ O(\log{n})) }[/math].

Алгоритм детерминирован в случае использования устойчивой сортировки вершин. Также алгоритм устойчив, так как используются операции, не приводящие к ошибкам округления - это операции сравнения для вещественных чисел и операции с целыми числами. Наибольшее число операций составляют операции сравнения.

Так как количество вершин на разных процессорах примерно одинаковое алгоритм является сбалансированным по числу операций на каждом процессоре.

Алгоритм достаточно прост и легко модифицируется в зависимости от критерия декомпозиции.

Программная реализация алгоритма

Особенности реализации последовательного алгоритма

Ниже приведен пример реализации последовательного алгоритма на языке C++. Следует отметить, что исходный массив вершин не изменяется, вся работа осуществляется с индексами. 

#include <algorithm>
#include <iostream>
#include <vector>

using namespace std;

#define N 5
#define M 5
#define STEP 0.01

#define N_DIMS 2
#define N_DOMAINS 6

vector<vector<double> > points_matrix(N_DIMS, vector<double>(N * M));
vector<vector<int> > graph_partition;

double span(vector<double> x, vector<int> idx)
{ 
    double max_value = x[idx[0]];
    double min_value = x[idx[0]];
    
    for (size_t i = 1; i < idx.size(); i++) {
        max_value = (x[idx[i]] > max_value) ? x[idx[i]] : max_value;
        min_value = (x[idx[i]] < min_value) ? x[idx[i]] : min_value; 
    }
    
    return max_value;
}

vector<int> bisect(vector<int> idx)
{
    double max_span = 0;
    double max_ind = 0;
    
    // finding coordinate with maximal span
    for (size_t i = 0; i < points_matrix.size(); i++) {
        double cur_span = span(points_matrix[i], idx);
        if (cur_span > max_span) {
            max_span = cur_span;
            max_ind = i;
        }
    }
    
    // sorting vertices along this coordinate
    sort(idx.begin(), idx.end(), [&](const int& a, const int& b) {
                return points_matrix[max_ind][a] < points_matrix[max_ind][b];
            });
    
    return idx;
}

void recursive_bisection(vector<int> idx, int k)
{
    // adding current domain to partition
    if (k < 2) {
        graph_partition.push_back(idx);
        return;
    }
    
    int k1 = (k + 1) / 2;
    int k2 = k - k1;
    
    // bisecting current graph
    vector<int> sorted_idx1 = bisect(idx);
    vector<int> sorted_idx2(make_move_iterator(sorted_idx1.begin() + k1 * sorted_idx1.size() / k),
                    make_move_iterator(sorted_idx1.end()));
    sorted_idx1.erase(sorted_idx1.begin() + k1 * sorted_idx1.size() / k, sorted_idx1.end());
    
    recursive_bisection(sorted_idx1, k1);
    recursive_bisection(sorted_idx2, k2);
}

int main()
{
    // example: uniform MxN-mesh 
    for(size_t i = 0; i < N; ++i)
        for(size_t j = 0; j < M; ++j) {
    	    points_matrix[0][M * i + j] = i * STEP;
	    points_matrix[1][M * i + j] = j * STEP;
	}

    vector<int> idx(M * N);
    iota(idx.begin(), idx.end(), 0);

    recursive_bisection(idx, K);
    
    // partitioning results
    for(size_t i = 0; i < graph_partition.size(); ++i) {
        for(size_t j = 0; j < graph_partition[i].size(); ++j)
            cout << graph_partition[i][j] << " ";
        cout << endl;
    }
}
