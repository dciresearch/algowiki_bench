ЧАСТЬ. Свойства и структура алгоритмов

Общее описание алгоритма

Алгоритм устойчивой кластеризации с иcпользованием связей ROCK (RObust Clustering using linKs) был совместно разработан Sudipto Guha, Rajeev Rastogi и Kyuseok Shim при работе в Bell Laboratories. Впервые алгоритм был опубликован в 1999 году в статье под названием "ROCK: A Robust Clustering Algorithm for Categorical Attributes", входящей в "ICDE '99 Proceedings of the 15th International Conference on Data Engineering".

Данный алгоритм принадлежит классу алгоритмов кластеризации, целью которых является разбиение данных на некоторое заранее заданное число групп. Подобные методы часто используются для анализа данных в различных областях, в том числе в маркетинге. Основная особенность алгоритма ROCK заключается в использовании связей между точками (количество общих соседей), в отличие от методов, базирующихся на различных метриках, таких как расстояние между точками (Евклидово и прочие). Такой подход улучшает определение глобальных зависимостей, а также наиболее эффективен при рассмотрении данных, свойства которых принимают достаточно малое конечное количество значений.

Одним из основных понятий для алгоритма ROCK является соседство двух точек. Пусть нам дана функция схожести [math]\displaystyle{ sim(p_i,p_j) }[/math], принимающая значения от 0 до 1, которая выражает схожесть или близость объектов(точек) [math]\displaystyle{ p_i }[/math] и [math]\displaystyle{ p_j }[/math]. Предполагается, что 1 соответствует абсолютной близости, и 0 - наоборот. Тогда при некоторой границе [math]\displaystyle{ \theta }[/math] между 0 и 1, если [math]\displaystyle{ sim(p_i,p_j) \geq \theta }[/math], то [math]\displaystyle{ p_i }[/math] и [math]\displaystyle{ p_j }[/math] будут соседними точками. Выбор Функции [math]\displaystyle{ sim(p_i,p_j) }[/math] и граничного значения [math]\displaystyle{ \theta }[/math] зависит входных данных и особенности реализации.

Вторым ключевым понятием являются связи. Функция связи [math]\displaystyle{ link(p_i,p_j) }[/math] определяется как количество общих соседей у [math]\displaystyle{ p_i }[/math] и [math]\displaystyle{ p_j }[/math]. Из такого определения сразу видно, что чем больше значение связи, тем больше вероятность, что эти точки принадлежат одному и тому же кластеру. Такой подход является более глобальным, по сравнению с использованием только близости двух точек, что позволяет снизить число ошибок, особенно в тех случаях, когда кластеры имеют несколько близких точек.

Алгоритм состоит из двух основных этапов. Изначально имеется [math]\displaystyle{ n }[/math] точек и [math]\displaystyle{ k }[/math] - желаемое число кластеров. На первом этапе вычисляются значения связей [math]\displaystyle{ link(p_i,p_j) }[/math] между всеми парами точек, каждая точка объявляется отдельным кластером. Для каждого кластера [math]\displaystyle{ i }[/math] создается локальная куча [math]\displaystyle{ q[i] }[/math], которая содержит все такие кластеры [math]\displaystyle{ j }[/math], что связь между ними не нулевая. Кроме этого, создается глобальная куча [math]\displaystyle{ Q }[/math], содержащая все кластеры. После этого алгоритм переходит ко второму этапу. Вторая часть представляет из себя цикл, на каждом шаге которого объединяются два кластера с максимальным значением функции полезности [math]\displaystyle{ g(i,j) }[/math], после чего вносятся соответствующие изменения в кучи. Алгоритм завершает работу в двух случаях: когда осталось [math]\displaystyle{ k }[/math] кластеров, или когда все связи между оставшимися кластерами равны нулю.

Математическое описание алгоритма

Дано множество [math]\displaystyle{ S }[/math] из [math]\displaystyle{ n }[/math] элементов и число [math]\displaystyle{ k }[/math]. Для каждых [math]\displaystyle{ p_i,p_j \in S }[/math] задана функция схожести [math]\displaystyle{ 0 \leq sim(p_i,p_j) \leq 1 }[/math]. Также дано число [math]\displaystyle{ 0 \leq \theta \leq 1 }[/math]. Дана функция [math]\displaystyle{ f( \theta ) }[/math].

Требуется разбить [math]\displaystyle{ S }[/math] на [math]\displaystyle{ k }[/math] не пересекающихся подмножеств(кластеров) [math]\displaystyle{ C_1, \dots, C_k }[/math] так, чтобы значение целевой функции [math]\displaystyle{ E_l }[/math]было как можно большим.

Определим следующие функции, полагая, что [math]\displaystyle{ p_i,p_j \in S. }[/math]

Функция, определяющая соседство двух точек:

[math]\displaystyle{ \begin{align} neib(p_i, p_j) = \begin{cases} 1, sim(p_i, p_j) \geq \theta,\\ 0, sim(p_i, p_j) \lt \theta. \end{cases} \\ \end{align} }[/math]

Функция, определяющая количество связей между точками:

[math]\displaystyle{ link(p_i, p_j) = \sum_{s\in S} neib(p_i,s) neib(p_j,s). }[/math]

Определим теперь целевую функцию, считая [math]\displaystyle{ n_i }[/math] количеством элементов в [math]\displaystyle{ C_i }[/math]:

[math]\displaystyle{ E_l = \sum_{i=1}^{k} n_i * \sum_{p_q, p_r \in C_i} \frac{link(p_q,p_r)}{n_{i}^{1+2f( \theta )}} }[/math]

Определим функцию связи для двух подмножеств [math]\displaystyle{ C_i, C_j }[/math]:

[math]\displaystyle{ link[C_i, C_j] = \sum_{p_q \in C_i, p_r \in C_j} link(p_i, p_j) }[/math]

Введем функцию полезности, выражающую то, насколько выгодно объединить подмножества [math]\displaystyle{ C_i, C_j }[/math]:

[math]\displaystyle{ g(C_i, C_j) = \frac{link[C_i,C_j]}{(n_i + n_j)^{1+2f( \theta )} - n_i^{1+2f( \theta )} - n_j^{1+2f( \theta )}} }[/math]

В данном алгоритме сначала все элементы разбиваются на [math]\displaystyle{ n }[/math] подмножеств, затем делается [math]\displaystyle{ n - k }[/math] шагов, на каждом из которых объединяются два подмножества, для которых значение функции полезности [math]\displaystyle{ g(i,j) }[/math] наибольшее.

Вычислительное ядро алгоритма

Вычислительное ядро алгоритма состоит из двух основных частей.

1. Вычисление всех связей между точками. Для каждой точки создается список соседей. Проходим по каждому такому списку и увеличиваем количество связей между всеми точками из списка, поскольку они имеют общую соседнюю точку (ту, которой принадлежит список).

2. Цикл по объединению кластеров, содержит [math]\displaystyle{ n-k }[/math] шагов, на каждом из которых мы находим наилучшие кластеры для объединения и перестраиваем соответствующие кучи.

Макроструктура алгоритма

Как написано в описании ядра алгоритма, алгоритм состоит из двух основных частей: Вычисление связей и Объединение кластеров.

Схема реализации последовательного алгоритма

Процедура кластеризации выглядит следующим образом: 

procedure cluster(S, k)
begin
  link := compute_links(S)
  for each s [math]\displaystyle{ \in }[/math] S do
    q[s] := build_local_heap(link, s)
  Q := build_global_heap(S, q)
  while size(Q) > k do {
    u := extract_max(Q)
    v := max(q[u])
    delete(Q, v)
    w := merge(u, v)
    for each x [math]\displaystyle{ \in }[/math] q[u] [math]\displaystyle{ \cup }[/math] q[v] do {
      link[x,w] := link[x, u] + link[x, v]
      delete(q[x], u); delete(q[x], v)
      insert(q[x],w, g(x,w)); insert(q[w], x, g(x,w))
      update(Q, x, q[x])
    }
    insert(Q,w, q[w])
    deallocate(q[u]), deallocate(q[v])
  }
end

1. Вычисление связей между каждой парой точек: 

procedure compute_links(S)
begin
  Compute nbrlist[i] for every point i in S
  Set link[i, j] to be zero for all i, j
  for i := 1 to n do {
    N := nbrlist[i]
    for j := 1 to |N| - 1 do
      for l := j + 1 to |N| do
        link[N[j],N[l]] := link[N[j],N[l]] + 1
  }
end

Дла каждой точки [math]\displaystyle{ i }[/math] строится список соседей [math]\displaystyle{ nbrlist[i] }[/math]. Поскольку любые две точки в таком списке имеют nbrlist[i] в качестве общего соседа, то для всех пар точек из списка увеличиваем значение функции связей.

2. Каждая точка объявляется отдельным кластером. Для каждого кластера [math]\displaystyle{ i }[/math] строится локальная куча [math]\displaystyle{ q[i] }[/math], которая поддерживается до конца работы алгоритма. [math]\displaystyle{ q[i] }[/math] содержит все такие кластеры [math]\displaystyle{ j }[/math], что [math]\displaystyle{ link[i,j] \neq 0 }[/math]. Кластеры [math]\displaystyle{ j }[/math] в [math]\displaystyle{ q[i] }[/math] отсортированы в порядке убывания функции полезности [math]\displaystyle{ g(i,j) }[/math]. Аналогичным образом создается глобальная куча [math]\displaystyle{ Q }[/math], содержащая все кластеры. Элементы внутри аналогично отсортированы в соответствии с их максимальным значением функции полезности.

3. Запускается while-цикл до тех пор, пока количество кластеров не станет равно [math]\displaystyle{ k }[/math]. На каждом шаге цикла берутся два кластера с максимальным значением [math]\displaystyle{ g(i,j) }[/math] и объединяются. Из глобальной кучи извлекается максимум, затем для этого кластера из его локальной кучи также извлекается максимум. По построению куч легко видеть, что это будет искомой парой. Далее происходит объединение кластеров, после чего для каждого кластера, который содержал в своей локальной куче один из данных, необходимо провести соответствующую коррекцию. Из глобальной кучи также удаляются два элемента и добавляется один новый с сохранением порядка.

Последовательная сложность алгоритма

Вычисление связей может рассматриваться как перемножение двух матриц размера [math]\displaystyle{ n }[/math], что можно реализовать за [math]\displaystyle{ O(n^{2.37}) }[/math]. Затраты памяти на хранение связей не превышают [math]\displaystyle{ n(n+1)/2 }[/math], когда любая пара точек - соседние. Однако в большинстве случаев среднее число соседей [math]\displaystyle{ m_a }[/math] и максимальное число соседей [math]\displaystyle{ m_m }[/math] значительно меньше [math]\displaystyle{ n }[/math], в связи с этим оценки сложности зависят от данных параметров. Сложность построения списка соседей оценивается [math]\displaystyle{ O(n^2) }[/math]. Для каждой точки, после вычисления списка своих соседей, алгоритм рассматривает все пары его соседей. Для каждой пары точка вносит одну связь. Если процесс повторяется для каждой точки и счетчик ссылок увеличивается на единицу для каждой пары соседей, то в конце концов, ссылка рассчитывает на будут получены все пары точек. Если [math]\displaystyle{ m_i }[/math] - число соседей точки [math]\displaystyle{ i }[/math], тогда для нее мы должны увеличить количество связей на единицу [math]\displaystyle{ m_i^2 }[/math] раз. Таким образом, сложность алгоритма является [math]\displaystyle{ \sum m_i^2 }[/math] и может быть оценено [math]\displaystyle{ O(n m_m m_a) }[/math]. Поскольку каждая точка [math]\displaystyle{ i }[/math] может иметь не более [math]\displaystyle{ \min \{ m_m m_i, n \} ) }[/math] связей, то общие затраты памяти не превышают [math]\displaystyle{ O(\min \{ n m_m m_a, n^2 \} ) }[/math].

Построение каждой кучи потребует не более [math]\displaystyle{ O(n) }[/math] времени (поскольку размер каждой кучи не может превышать [math]\displaystyle{ n }[/math]) Сортировка каждой кучи потребует [math]\displaystyle{ O( n \log{} n) }[/math]. Рассмотрим теперь основной while-цикл. Он содержит [math]\displaystyle{ O(n) }[/math] итераций, где основная сложность каждого шага приходится на for-цикл. В худшем случае потребуется вставить новый кластер в [math]\displaystyle{ O(n) }[/math] локальных куч размера [math]\displaystyle{ n }[/math], что потребует [math]\displaystyle{ O( n \log{} n) }[/math] времени. Таким образом, сложность всего внешнего цикла составляет [math]\displaystyle{ O(n^2 \log{} n) }[/math] в худшем случае. Затраты памяти зависят от начального размера локальных куч, поскольку при слиянии кластеров их старые кучи удаляются, а размер новой не превышает суммы старых. Поскольку каждая куча сожержит лишь кластеры с ненулевыми связями, то сложность совпадает с первой частью и равна [math]\displaystyle{ O(\min \{ n m_m m_a, n^2 \} ) }[/math].

Итоговые оценки для всего алгоритма:

Сложность по времени:

[math]\displaystyle{ O(n^2 + n m_m m_a + n^2 \log{} n) }[/math]

Сложность по памяти:

[math]\displaystyle{ O(\min \{ n^2, n m_m m_a \} ) }[/math]

Список обозначений:

[math]\displaystyle{ m_a }[/math] - среднее число соседей
[math]\displaystyle{ m_m }[/math] - максимальное число соседей
[math]\displaystyle{ m_i }[/math] - число соседей точки [math]\displaystyle{ i }[/math]
[math]\displaystyle{ n }[/math] - размер входных данных

Информационный граф

Обозначения :

  • CN - вершина построения соседей: заполнение nbrlist[i].
  • CLM - вершина построения матрицы связей: заполнение link[i][j].
  • CLH - вершина построения локальных куч: заполнение q[i].
  • CGH - вершина построения глобальной кучи: заполнение Q.
  • GC - вершина поиска и слияние топ 2 кластеров: построение w.
  • RL - пересчет матрицы связей: заполнение link[x,w].
  • UPDATE - Обновление глобальной кучи: обновление Q.


Как видно из графа в алгоритме есть ряд узких мест. Рассмотрим их подробнее:

1) Вершина построения матрицы links. Данные вычисления не могут быть прямо распараллелены, нельзя для каждого списка соседей запустить данную функцию. Это связано с тем, что во время выполнения данных вычислений необходимо производить запись в матрицу и любой список может писать в любое место матрицы. В худшем случае (когда все соседи всем) при параллельном запуске возможны постоянные конфликты. Но в данной вершине все же есть потенциал для параллельной работы. Он заключается в том, что можно в параллели обрабатывать список соседей. При подходе в лоб нагрузка на ядра будет не равномерна.

Так же данный пункт можно реализовать иначе. Но затраты по памяти возрастут в N раз. Можно параллельно обрабатывать каждый вектор соседей. При среднем количестве соседей [math]\displaystyle{ m_a }[/math] это займет [math]\displaystyle{ O(m_a ^ 2) }[/math] операций (или если мы имеем [math]\displaystyle{ n^2 }[/math] ядер, то можно и за [math]\displaystyle{ O(m_a) }[/math] + [math]\displaystyle{ O(log(n)) }[/math] для объединения N матриц.

2) Вершина построения глобальной кучи. В данной вершине необходимо добавить все вершины и после отсортировать в зависимости от наилучшего значения полезности каждой локальной кучи. Сортировку можно распараллелить.

3) Вершина взятия топ 2 кластеров. Узкая, но малозатратная вершина.

4) Вершина обновления куч. Так же узкая вершина в которой нужно в каждой локальной куче вставить в нужное место кластер и так же поступить с глобальной кучей.

Ресурс параллелизма алгоритма

Кроме нескольких узких мест алгоритма, которые не поддаются распараллеливанию, в целом алгоритм неплохо может быть переложен на параллельную архитектуру. Рассчитаем сложность алгоритма.

1) На первом этапе происходит вычисление соседей. Затраты данных операций при условии достаточного количества ядер [math]\displaystyle{ T_1 = O(n) }[/math]

2) На этапе построения связей [math]\displaystyle{ n }[/math] этапов в каждом из которых можно сделать [math]\displaystyle{ m }[/math] расчетов(с учетом распараллеливания), где [math]\displaystyle{ m }[/math] - количество соседей. В худшем случае [math]\displaystyle{ T_2 = O(n^2) }[/math] в среднем случае [math]\displaystyle{ T_2 = O(n * m_a) }[/math], где [math]\displaystyle{ m_a }[/math] среднее ожидаемое число соседей.

3) Построение одной кучи это сложность [math]\displaystyle{ O(n) }[/math]. Плюс для каждой кучи сортировка [math]\displaystyle{ O(n * log(n)) }[/math]. Соответственно итоговая сложность создания локальных куч [math]\displaystyle{ T_3 = O(n * log(n)) }[/math].

4) Построение и сортировка глобальной кучи так же [math]\displaystyle{ T_4 = O(n * log(n)) }[/math].

5) Цикл в котором происходит выбор кластеров, сливание, пересчет и обновление куч. Игнорируем выбор кластеров (достать из кучи [math]\displaystyle{ O(1) }[/math] ). Для всех элементов кучи слитых кластеров пересчитываем значение связи, вставляем в кучу выбранного кластера информацию о новом кластере, удаляем старое. Делается это за [math]\displaystyle{ O(log(n)) }[/math]. Соответственно в худшем случае, одна итерация цикла это [math]\displaystyle{ T_i = O(log(n)) }[/math]. Количество итераций n - k. Значит

[math]\displaystyle{ T_5 = O((n - k) * log(n)) }[/math]. При k = 1, [math]\displaystyle{ T_5 = O(n * log(n)) }[/math]

Итоговая сложность в худшем случае равна:

[math]\displaystyle{ T_1 + T_2 + T_3 + T_4 + T_5 = O(n) + O(n^2) + O(n * log(n)) + O(n * log(n)) + O(n * log(n)) = O(n^2) }[/math]

Итоговая сложность в среднем случае равна:

[math]\displaystyle{ O(n * m_a) + O(n * log(n)) }[/math].

Тут важно понимать, что в зависимости от данных как [math]\displaystyle{ log(n) }[/math] может быть больше [math]\displaystyle{ m_a }[/math], так и наоборот.

Сложность по времени:

[math]\displaystyle{ O(n * (m_a + log(n))) }[/math].

Входные и выходные данные алгоритма

Входные данные: Множество [math]\displaystyle{ S }[/math] из [math]\displaystyle{ n }[/math] элементов, число кластеров [math]\displaystyle{ k }[/math]. В зависимости от реализации, некоторые параметры алгоритма могут также подаваться на вход или быть определены заранее.

Объем входных данных: Зависит от типа элементов из множества [math]\displaystyle{ S }[/math], поскольку алгоритм может быть реализован для широкого класса данных. В общем случае требуется хранить массив из [math]\displaystyle{ n }[/math] элементов.

Выходные данные: Метки класса (номер кластера) для каждого элемента.

Объем выходных данных: Для каждого входного элемента достаточно вернуть соответствующую ему метку (число), поэтому минимальный размер выхода: массив из [math]\displaystyle{ n }[/math] чисел.

Свойства алгоритма

Алгоритм является детерминированным.

Алгоритм является устойчивым.

Вычислительная мощность алгоритма равна:

[math]\displaystyle{ \frac{O(n^2 + n m_m m_a + n^2 \log{} n)}{n} }[/math].

Отношение последовательной и параллельной сложности:

[math]\displaystyle{ \frac{O(n^2 + n m_m m_a + n^2 \log{} n)}{O(n * (m_a + log(n)))} }[/math].


К свойствам алгоритма можно отнести то, что сложность в среднем зависит от данных. Если растет среднее ожидаемое количество соседей, то растет и средняя сложность алгоритма. В худшем случае она может достигать [math]\displaystyle{ O(n^2) }[/math] для данных с большой кучностью (одна большая плотная куча, где по факту 1 кластер). Но, если же среднее ожидаемое число соседей меньше [math]\displaystyle{ log(n) }[/math], то сложность алгоритма будет [math]\displaystyle{ O(n *log(n)) }[/math]. В целом можно взять оценку [math]\displaystyle{ O(n * m_m) }[/math], где [math]\displaystyle{ m_m }[/math] максимальное количество соседей.

Масштабируемость алгоритма

Как можно видеть из графа, представленного выше, в алгоритме есть 3 основных места для распараллеливания: 1) Составление матрицы связей 2) Построение локальных куч 3) Основной цикл алгоритма

Теоретическая оценка сложности алгоритма распараллеленного на p потоков:

[math]\displaystyle{ O(\frac{n}{p}(n + m_m m_a + n\log{} n)) }[/math].

Соответственно: 1) При одинаковых входных данных, время работы обратно пропорционально количеству потоков. 2) При одинаковом количестве потоков, время зависит от входных данных кубически в худшем случае.

Масштабируемость реализации

Реализация алгоритма тестировалась на IBM pSeries 690 HPC Regatta.

  • Максимальное количество потоков, способных работать в параллельном режиме: 16.
  • Процессоры POWER4 1,3 ГГц; 16-процессорная архитектура SMP

Параметры запусков: 1) Запуски осуществлялись на задачах объемом 400, 800, 1600, 2400 точек. 2) Запуски осуществлялись на 1, 2, 4, 8, 16 потоках. 3) Количество кластеров = 2, [math]\displaystyle{ \theta }[/math] = 0.3, соседями считались все точки в радиусе 0.3 .
