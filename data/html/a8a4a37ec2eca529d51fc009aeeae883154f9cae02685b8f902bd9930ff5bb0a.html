Свойства и структура алгоритма

Общее описание алгоритма

Алгоритм k-means (k средних) - один из наиболее популярных алгоритмов кластеризации. Наиболее простой, но в то же время достаточно неточный метод кластеризации в классической реализации.

Алгоритм был разработан в 1956 году математиком Гуго Штейнгаузом [1], и почти одновременно его изобрел Стюарт Ллойд [2]. Особую популярность алгоритм снискал после работы Джеймса Маккуина [3]

Алгоритм кластеризации k-means решает задачу распределения [math]\displaystyle{ N }[/math] наблюдений (элементов векторного пространства) на заранее известное число кластеров [math]\displaystyle{ K }[/math]. Действие алгоритма таково, что он стремится минимизировать среднеквадратичное отклонение на точках каждого кластера.

Алгоритм k-means является итерационным алгоритмом кластеризации. На каждой итерации происходит пересчет центра масс для каждого кластера, полученного на предыдущем шаге, затем исходные векторы заново распределяются по кластерам в соответствии с тем, какой из новых центров оказался ближе по выбранной метрике. Алгоритм завершается, когда на какой-то итерации не происходит изменения кластеров.

Математическое описание алгоритма

Исходные данные:

  • множество наблюдений [math]\displaystyle{ X = \{x_1, x_2, ..., x_n\} }[/math], где каждое наблюдение [math]\displaystyle{ x_i \in R^d, i = 1, ..., n }[/math];
  • количество кластеров [math]\displaystyle{ k \in N, k \leq n }[/math]

Обозначения:

  • [math]\displaystyle{ S = \{S_1, S_2, ..., S_k \} }[/math] - множество кластеров, которые удовлетворяют следующим условиям:
    • [math]\displaystyle{ S_i \bigcap S_j = \emptyset, i \neq j }[/math];
    • [math]\displaystyle{ X = {\bigcup \limits _{i = 1}^k S_i} }[/math].
  • [math]\displaystyle{ \mu_i \in R^d, i = 1, ..., k }[/math] - центр масс кластера [math]\displaystyle{ S_i }[/math]
  • [math]\displaystyle{ d(u, v) }[/math] - расстояние между векторами [math]\displaystyle{ u \in R^m, v \in R^m }[/math]

Выходные данные:

  • [math]\displaystyle{ L = (l_1, l_2, ..., l_n) }[/math] - набор меток, где метка [math]\displaystyle{ l_i \in N_{[1, k]} }[/math] - является порядковым номером кластера, к которому принадлежит вектор [math]\displaystyle{ x_i }[/math]: [math]\displaystyle{ x_i \in S_{l_i} }[/math]


Цель алгоритма k-means - распределить наблюдения из входного множества [math]\displaystyle{ X }[/math] по [math]\displaystyle{ k }[/math] кластерам [math]\displaystyle{ S = \{S_1, S_2, ..., S_k \} }[/math] таким образом, чтобы сумма квадратов расстояний от каждой точки кластера до его центра масс по всем кластерам была минимальной:

[math]\displaystyle{ \arg\min_{S} \sum_{i=1}^{k} \sum_{x \in S_i} (d(x, \mu_i))^2 }[/math],


Алгоритм состоит из следующих шагов:

  1. Инициализация центров масс
    На данном шаге задаются начальные значения центров масс [math]\displaystyle{ \mu_1^1, ..., \mu_k^1 }[/math]. Существует несколько способов их выбора. Они будут рассмотрены ниже.
  2. t-ый шаг итерации:
    • Распределение векторов по кластерам
      На данном шаге каждый вектор [math]\displaystyle{ x_i \in X }[/math] распределяется в свой кластер [math]\displaystyle{ S_j^t }[/math] так, что:
      [math]\displaystyle{ l_i^t = \arg \min_{j} (d(x_i, \mu_j^t))^2 , j = 1, ..., k; i = 1, ..., n }[/math]
    • Пересчет центров масс кластеров
      На данном шаге происходит пересчет центров масс кластеров, полученных на предыдущем этапе:
      [math]\displaystyle{ \mu_i^{t+1} = \frac{1}{|S_i^t|} \sum_{x \in S_i^t} x }[/math]; [math]\displaystyle{ i = 1, ..., k }[/math]
  3. Критерий останова
    [math]\displaystyle{ \mu_i^t = \mu_i^{t+1}, }[/math] для всех [math]\displaystyle{ i = 1, ..., k }[/math]


Способы инициализации начальных данных:

  1. Метод Forgy
    Случайным образом выбираются [math]\displaystyle{ k }[/math] векторов из множества наблюдений [math]\displaystyle{ X }[/math]. Эти вектора используются в качестве центров масс кластеров [math]\displaystyle{ \mu_1, ..., \mu_k }[/math]
  2. Метод случайного разбиения (Random Partition) [4]
    Каждый вектор [math]\displaystyle{ x_i, i = 1, .., n }[/math] случайным образом распределяется в кластер [math]\displaystyle{ S_j, j = 1, .., k }[/math], затем для каждого кластера вычисляется его центр масс [math]\displaystyle{ \mu_j }[/math].

Вычислительное ядро алгоритма

Вычислительном ядром алгоритма является шаг 2, состоящий из следующих этапов:

  1. распределение векторов по кластерам;
  2. пересчет центров масс кластеров.

Распределение векторов по кластерам заключается в следующем: для каждого вектора [math]\displaystyle{ x_i \in X, i = 1, ..., n }[/math] необходимо посчитать расстояние между этим вектором и центром масс кластера [math]\displaystyle{ \mu_j^t, j = 1, ..., k }[/math]. Следовательно, на каждой итерации необходимо выполнить [math]\displaystyle{ nk }[/math] операций вычисления расстояния между векторами.

Пересчет центров масс кластеров заключается в следующем: для каждого кластера [math]\displaystyle{ S_i^t \in S, i = 1, ..., k }[/math] необходимо пересчитать кластер по формуле, приведенной в пункте выше. Следовательно, на каждой итерации необходимо выполнить [math]\displaystyle{ k }[/math] операций пересчета центров масс кластеров.

Макроструктура алгоритма

  1. Макрооперация "Расстояние между векторами"
    В данном алгоритме используется Евклидова метрика:
    [math]\displaystyle{ v \in R^m }[/math] и [math]\displaystyle{ u \in R^m: d(v, u) = \sqrt{\sum_{j=1}^{m} (v_j - u_j)^2} }[/math];
  2. Макрооперация "Пересчет центра масс кластера"
    [math]\displaystyle{ \mu_i^{t+1} = \frac{1}{|S_i^t|} \sum_{x \in S_i^t} x }[/math]

Таким образом, алгоритм в терминах макроопераций выглядит следующим образом:

  1. Инициализация центров масс

    Метод Forgy: центры масс [math]\displaystyle{ \mu_j^1, j = 1, ..., k }[/math] выбираются случайным образом.

    Метод случайного разбиения: вектора [math]\displaystyle{ x_i \in X }[/math] случайным образом распределяются по кластерам. Для каждого кластера выполняется макрооперация "Пересчет центра масс кластера" для нахождения [math]\displaystyle{ \mu_j^1 }[/math].

  2. t-ый шаг итерации:
    • Распределение векторов по кластерам
      На данном шаге для каждого вектора [math]\displaystyle{ x_i \in X }[/math] k раз выполняется макрооперация "Расстояние между векторами" для нахождения расстояния между [math]\displaystyle{ x_i }[/math] и [math]\displaystyle{ \mu_j^t, j = 1, ..., k }[/math]. Затем для каждого вектора [math]\displaystyle{ x_i }[/math] находится минимальное расстояние.
    • Пересчет центров масс кластеров
      На данном шаге для каждого кластера выполняется макрооперация "Пересчет центра масс" для нахождения [math]\displaystyle{ \mu_j^{t+1} }[/math].
  3. Критерий останова
    [math]\displaystyle{ \mu_i^t = \mu_i^{t+1}, }[/math] для всех [math]\displaystyle{ i = 1, ..., k }[/math]

Схема реализации последовательного алгоритма

Псевдокод алгоритма: 

Входные данные  : Множество векторов [math]\displaystyle{ X }[/math], количество кластеров [math]\displaystyle{ k }[/math]
Выходные данные : Набор меток [math]\displaystyle{ L }[/math] принадлежности к кластеру
1  Инициализация центров масс [math]\displaystyle{ \mu_i^1, i = 1, ..., k }[/math];
2  t := 1;
3  Для каждого вектора [math]\displaystyle{ x_i \in X, i = 1, ..., n: }[/math] [math]\displaystyle{ l_i^t = \arg \min_{j} (d(x_i,\mu_j^t))^2 , j = 1, ..., k }[/math];
4  Для каждого кластера [math]\displaystyle{ S_i^t, i = 1, ..., k }[/math] выполняется макрооперация "Пересчет центра масс";
5  if ([math]\displaystyle{ \exists i = 1, ..., k: \mu_i^t \neq \mu_i^{t+1} }[/math]) {
6      t := t + 1;
7      goto 3;
8  } else {
9      stop;
10 };

Последовательная сложность алгоритма

Подсчитаем количество операций для каждого шага алгоритма.

  1. Инициализация:
    • Метод Forgy: [math]\displaystyle{ N_{\rm init} = 0 }[/math]
    • Метод случайного разбиения:
      • Количество операций деления: [math]\displaystyle{ N^{/}_{\rm init} = kd }[/math];
      • Количество операций сложения: [math]\displaystyle{ N^{+}_{\rm init} = d(n - k) }[/math].
  2. Распределение [math]\displaystyle{ n }[/math] векторов [math]\displaystyle{ x_i \in R^d }[/math] по [math]\displaystyle{ k }[/math] кластерам на одной итерации:
    • Количество операций умножения: [math]\displaystyle{ N^{*}_{\rm distr} = knd }[/math];
    • Количество операций сложения: [math]\displaystyle{ N^{+}_{\rm distr} = kn(d - 1) }[/math];
    • Количество операций вычитания: [math]\displaystyle{ N^{-}_{\rm distr} = knd }[/math];
    • Количество операций взятия минимума: [math]\displaystyle{ N^{\rm min}_{\rm distr} = n(k - 1) }[/math].
  3. Пересчет центра масс [math]\displaystyle{ \mu_i \in R^d }[/math] для [math]\displaystyle{ k }[/math] кластеров на одной итерации:
    • Количество операций деления: [math]\displaystyle{ N^{/}_{\rm update} = kd }[/math];
    • Количество операций сложения: [math]\displaystyle{ N^{+}_{\rm update} = d(n - k) }[/math].

Следовательно, в случае если алгоритм сошелся за [math]\displaystyle{ i }[/math] итераций, получаем:

  • Операций сложения/вычитания: [math]\displaystyle{ N^{+,-}_{\rm k-means} = N^{+}_{\rm init} + i \cdot (N^{+}_{\rm distr} + N^{-}_{\rm distr} + N^{+}_{\rm update}) = d(n - k) + i \cdot (kn(d-1)+knd+d(n-k)) \thicksim O(iknd) }[/math]
  • Операций умножения/деления: [math]\displaystyle{ N^{*,/}_{\rm k-means} = N^{/}_{\rm init} + i \cdot (N^{*}_{\rm distr} + N^{/}_{\rm update}) = kd + i \cdot (knd+kd) \thicksim O(iknd) }[/math]

Таким образом, последовательная сложность алгоритма k-means для [math]\displaystyle{ n }[/math] [math]\displaystyle{ d }[/math]-мерных векторов и [math]\displaystyle{ k }[/math] кластеров за [math]\displaystyle{ i }[/math] итераций, требуемых для сходимости алгоритма:

[math]\displaystyle{ O(iknd) }[/math]

Информационный граф

Рассмотрим информационный граф алгоритма k-means. На рисунке 1 представлена общая схема алгоритма k-means, согласно разделу "Схема реализации последовательного алгоритма". Вершина [math]\displaystyle{ \rm Init }[/math] - этап инициализации. Вершина [math]\displaystyle{ \rm Distribute }[/math] - этап распределения векторов по кластерам. Вершина [math]\displaystyle{ \rm Update }[/math] - этап пересчета центров масс кластеров.


На рисунке 2 представлен информационный граф этапа распределения векторов по кластерам. На вход данному этапу подают множество векторов [math]\displaystyle{ x_1, x_2, ..., x_n }[/math] из входных данных и множество центров масс кластеров [math]\displaystyle{ \mu^t_1, ..., \mu^t_k }[/math], полученных с шага инициализации или с предыдущей итерации. Для каждой пары векторов [math]\displaystyle{ x_i, \mu^t_j, i = 1, ..., n; j = 1,..., k }[/math] считается расстояние между ними (вершина [math]\displaystyle{ \rm dist }[/math]). Информационный граф вычисления расстояния между двумя векторами рассмотрен ниже (рисунок 3). Затем выполняется операция нахождения минимума (вершина [math]\displaystyle{ \rm min }[/math]), в результате которой каждому вектору [math]\displaystyle{ x_i, i = 1, ..., n }[/math] приписывается метка [math]\displaystyle{ l^t_i }[/math], равная порядковому номеру кластера [math]\displaystyle{ S^t_j, j = 1 ..., k }[/math], которому принадлежит данный вектор: [math]\displaystyle{ x_i \in S^t_j }[/math].


На рисунке 3 представлен информационный граф вычисления расстояния между двумя векторами [math]\displaystyle{ x_i = (x_{i1}, ..., x_{id}), i = 1, ..., n }[/math] и [math]\displaystyle{ \mu^t_j = (\mu^t_{j1}, ..., \mu^t_{jd}) , j = 1, ..., k }[/math]. Выполняется операция поэлементного вычитания двух векторов (вершины [math]\displaystyle{ - }[/math]), затем возведение в квадрат (вершины [math]\displaystyle{ \rm sqr }[/math]), затем суммирование полученных результатов (вершина [math]\displaystyle{ + }[/math]). На выходе получаем квадрат расстояния между векторами.


На рисунке 4 представлен информационный граф этапа пересчета центров масс кластеров [math]\displaystyle{ \mu^t_1, \mu^t_2,..., \mu^t_k }[/math]. Для каждого кластера [math]\displaystyle{ S^t_j, j = 1, ..., k }[/math] выполняется операция суммирования (вершина [math]\displaystyle{ \rm sum_j }[/math]) векторов, которые принадлежат данному кластеру. Кроме того, для каждого кластера выполняется операция определения количества элементов в нем (вершина [math]\displaystyle{ \rm size_j }[/math]). Затем выполняется операция деления (вершина [math]\displaystyle{ / }[/math]). На выходе получаем новые центры масс кластеров [math]\displaystyle{ \mu^{t+1}_1, \mu^{t+1}_2,..., \mu^{t+1}_k }[/math].

Ресурс параллелизма алгоритма

Вычислительное ядро алгоритма имеет большие возможности для параллелизма:

  • Распределение векторов по кластерам: вектора [math]\displaystyle{ x_i, x_j, i \neq j; i, j = 1, ..., n }[/math] могут быть распределены по кластерам независимо друг от друга;
  • Пересчет центров масс кластеров: центры масс кластеров [math]\displaystyle{ \mu_i, \mu_j, i \neq j; i, j = 1, ..., k }[/math] могут быть пересчитаны независимо друг от друга.

Однако, этап пересчета центров масс кластеров зависит от этапа распределения векторов по кластерам, так что эти этапы должны выполняться строго последовательно. Таким образом, параллельная сложность алгоритма может быть вычислена следующим образом:
[math]\displaystyle{ N_{\rm k-means} = i \cdot (N_{\rm distr} + N_{\rm update}) }[/math], где [math]\displaystyle{ i }[/math] - количество итераций, необходимых для сходимости алгоритма, [math]\displaystyle{ N_{\rm distr} }[/math] - параллельная сложность этапа распределения векторов по кластерам, [math]\displaystyle{ N_{\rm update} }[/math] - параллельная сложность этапа пересчета центров масс кластеров.


Рассчитаем параллельную сложность [math]\displaystyle{ N_{\rm distr} }[/math] этапа распределения векторов по кластерам в предположении наличия неограниченного числа процессоров для одной итерации. Для каждой пары векторов [math]\displaystyle{ (x_i, \mu_j), i = 1,...,n; j = 1, ..., k }[/math] операция вычисления расстояния выполняется независимо.

  • При выполнении операция вычисления расстояния операции вычитания и умножения выполняются независимо друг от друга, поэтому требуется только одно вычитание и одно умножение. Число операций сложения: [math]\displaystyle{ N^{+}_{\rm distr} = O(\log(d)) }[/math] согласно алгоритму нахождения частичной суммы элементов массива путем сдваивания;
  • Для нахождения минимума среди [math]\displaystyle{ k }[/math] элементов требуется [math]\displaystyle{ \log(k)) }[/math] операций сравнения.

Таким образом, получаем, что [math]\displaystyle{ N_{\rm distr} = O(\log(kd)) }[/math]


Рассчитаем параллельную сложность [math]\displaystyle{ N_{\rm update} }[/math] этапа пересчета центров масс кластеров в предположении наличия неограниченного числа процессоров для одной итерации. Нахождение центра масс [math]\displaystyle{ \mu_j, j = 1, ..., k }[/math] кластера [math]\displaystyle{ S_j }[/math] может выполняться независимо от нахождения центров масс других кластеров. Таким образом, получаем, что [math]\displaystyle{ N_{\rm update} \leq O(\log(n)) }[/math] в худшем случае, когда почти все векторы находятся в одном кластере.


Итоговая параллельная сложность алгоритма:
[math]\displaystyle{ N_{\rm k-means} \leq i \cdot (\log(kd) + \log(n)) \thicksim O(i \cdot \log(knd)); i }[/math] - количество итераций, необходимых для сходимости.

Входные и выходные данные алгоритма

Входные данные:

  • [math]\displaystyle{ n }[/math] векторов [math]\displaystyle{ x_i \in R^d, i = 1, ..., n }[/math];
  • число кластеров [math]\displaystyle{ k \in N_{[1,n]} }[/math].

Объем входных данных: [math]\displaystyle{ nd }[/math] действительных чисел, 1 целое положительное число

Выходные данные:

  • вектор меток [math]\displaystyle{ L \in N^n }[/math].

Объем выходных данных: [math]\displaystyle{ n }[/math] целых неотрицательных чисел.

Свойства алгоритма

Достоинства
  1. Алгоритм прозрачный и понятный, за счет чего очень прост в реализации;
  2. Алгоритм имеет высокую скорость работы в случае выбора оптимальных начальных значений центров масс кластеров.
Недостатки
  1. Число кластеров является входным аргументом алгоритма. Таким образом, некорректный выбор данного параметра может привести к плохим результатам работы алгоритма, поэтому зачастую проводят несколько прогонов алгоритма с разными значениями [math]\displaystyle{ k }[/math], чтобы подобрать оптимальный;
  2. Алгоритм может сойтись к локальному минимуму (достижение глобального минимума не гарантируется);
  3. Результат сильно зависит от выбора начальных значений центров масс кластеров. Существует улучшенная версия алгоритма - k-means++ [8], которая предлагает свой способ нахождения начальных оптимальных значений центров масс кластеров;
  4. Чувствительность к выбросам и шумам, так как они учитываются при вычислении центров масс кластеров.
Устойчивость
Алгоритм является устойчивым к погрешностям во входных данных, так как при вычислении центров кластеров расстояния между объектами усредняются, что приводит к уменьшению ошибки. Алгоритм также является устойчивым к погрешностям, допускаемых при вычислениях, так как операция сложения на каждой новой итерации выполняется над входными данными.
Сбалансированность

Множество входных векторов можно равномерно разделить между параллельными вычислителями. Центры всех кластеров можно распространить на все вычислители (так как их заведомо меньше, чем число входных векторов). В таком случае на каждой итерации определение для каждого объекта ближайшего кластера представляет собой вычисление расстояния от каждого входного вектора, находящегося на вычислителе, до каждого кластера, и является сбалансированной операцией. После данного этапа происходит пересчёт центров кластеров. Данная операция является несбалансированной в случаях, когда число объектов в одном из кластеров значительно больше числа объектов в других кластерах, из-за чего один кластер занимает большое число вычислителей, а остальные занимают по одному или несколько вычислителей. В таком случае для данного кластера потребуется вычислить центр алгоритмом нахождения частичной суммы элементов массива путем сдваивания. Данная операция представляет несбалансированность порядка [math]\displaystyle{ O(\log (kn)) }[/math]. После данного шага происходит сбалансированная операция рассылки центров кластеров на все вычислители.

В идеальном случае параллелизации алгоритм не является сбалансированным, однако в реальных задачах, когда [math]\displaystyle{ n \gt \gt p }[/math], где [math]\displaystyle{ p }[/math] - количество вычислителей, эта несбалансированность сглаживается наличием объектов из каждого кластера на каждом вычислителе

Соотношение последовательной и параллельной сложности
[math]\displaystyle{ {O(iknd) \over O(i \cdot \log(knd))} \thicksim O \bigg( {knd \over \log(knd)} \bigg) }[/math]
Вычислительная мощность

Последовательный алгоритм: [math]\displaystyle{ {O(iknd) \over nd+n+1} \thicksim {O(ikd) \over d+1} \thicksim O(ik) }[/math], где [math]\displaystyle{ n }[/math] - число входных векторов, [math]\displaystyle{ d }[/math] - размерность векторов, [math]\displaystyle{ k }[/math] - число кластеров, [math]\displaystyle{ i }[/math] - число итераций, требуемое для сходимости

Параллельный алгоритм: [math]\displaystyle{ O(i \cdot \log(knd)) \over nd+n+1 }[/math]

Детерминированность
Алгоритм является недетерминированным, так как результат зависит от выбора исходных центров кластеров, а их оптимальный выбор неизвестен.

Исследование проводилось на суперкомпьютере "Ломоносов" Суперкомпьютерного комплекса Московского Государственного Университета имени М.В. Ломоносова

Набор данных для тестирования состоял из 946000 векторов размерности 2 (координаты на сфере)

Набор и границы значений изменяемых параметров запуска реализации алгоритма:

  • число процессов (виртуальных ядер) [8 : 512];
  • число кластеров [128 : 384].

В результате проведённых экспериментов был получен следующий диапазон эффективности реализации алгоритма:

  • минимальная эффективность реализации [math]\displaystyle{ 2,47% }[/math] достигается при делении исходных данных на 128 кластеров с использованием 512 процессов;
  • максимальная эффективность реализации [math]\displaystyle{ 7,13% }[/math] достигается при делении исходных данных на 352 кластера с использованием 8 процессов.

На рисунках 5 и 6 соответственно представлены графики зависимости производительности и эффективности параллельной реализации k means от числа кластеров и числа процессов.

По рис. 5 можно отметить практически полное отсутствие роста производительности с увеличением числа процессов от 256 до 512 при минимальном размере задачи. Это связано с быстрым ростом накладных расходов по отношению к крайне низкому объёму вычислений. При росте размера задачи данный эффект пропадает, и при одновременном пропорциональном увеличении числа кластеров и числа процессов рост производительности становится близким к линейному.

Исследовалась параллельная реализация алгоритма k means на MPI.

Были получены следующие оценки масштабируемости реализации алгоритма k means:

  • По числу процессов: [math]\displaystyle{ -0.02209 }[/math]. Следовательно, с ростом числа процессов эффективность уменьшается. На рис. 6 можно наблюдать плавное и равномерное снижение производительности по мере увеличения числа процессов при неизменном числе кластеров, что свидетельствует об относительно невысоком росте накладных расходов на передачу данных между процессами и преобладании объёма вычислений над объёмом пересылок данных по сети.
  • По размеру задачи: [math]\displaystyle{ 0.01252 }[/math]. Следовательно, с ростом размера задачи (числа кластеров) эффективность увеличивается. При этом объём пересылок данных по сети пропорционален [math]\displaystyle{ (n + k) \cdot p }[/math] (где [math]\displaystyle{ k }[/math] - число кластеров, [math]\displaystyle{ n }[/math] - число входных векторов, [math]\displaystyle{ p }[/math] - число процессов) таким образом, поскольку [math]\displaystyle{ k \lt \lt n }[/math], рост накладных расходов с ростом числа кластеров при неизменном числе процессов и входных векторов представляет собой незначительную величину.
  • Общая оценка: [math]\displaystyle{ -0.00081 }[/math]. Таким образом, с ростом и размера задачи, и числа процессов эффективность уменьшается. Это связано с тем, что отношение объёма вычислений к объёму передаваемых данных изменяется пропорционально [math]\displaystyle{ {kn \over (n + k) \cdot p} \thicksim {k \over p} }[/math], что представляет собой невысокий коэффициент, но при этом позволяет параллельной реализации не деградировать до нулевой эффективности при значительном увеличении числа процессов.

  • OpenCV - содержит реализацию k-means на C++. А также есть обертки для языков Python и Java
  • SciPy - содержит реализацию k-means на языке Python
  • Scikit-learn - содержит реализацию k-means на языке Python
